# telegram-ai-moderator

AI-модератор и ассистент для групповых чатов Telegram: автоматически фильтрует
спам/рекламу/токсичность, выдаёт предупреждения и муты, отвечает на вопросы
по истории переписки и присылает ежедневные/еженедельные AI-сводки
обсуждений.

## Возможности

- Модерация сообщений: эвристики (антифлуд, антиповтор) + классификация
  через LLM (OpenAI-совместимый Chat Completions API).
- Гибкие меры: предупреждение, удаление сообщения, временный мут — по
  настраиваемой матрице строгости/уверенности/серьёзности нарушения.
- Ответы на вопросы участников по истории чата (`@бот вопрос`).
- Ежедневные и еженедельные AI-сводки обсуждений, отправляемые в группу.
- Статистика активности участников и статистика модерации (`/stats`,
  `/top`, `/activity`, `/moderation`, `/notifications`).
- Панель администратора чата с inline-кнопками (`/settings`).

## Режимы работы: webhook vs long polling

Режим определяется значением `WEBHOOK_URL`:

- **Пусто (`""`)** → long polling. Бот сам опрашивает Telegram за
  обновлениями. HTTP-сервер (`/health`) при этом всё равно поднимается —
  это нужно для прохождения health-check у Render (см. ограничения ниже).
- **`true` / `1` / `yes` / `on`** → webhook-режим, а базовый URL берётся
  автоматически из `RENDER_EXTERNAL_URL` (эту переменную Render
  устанавливает сам для каждого веб-сервиса). Это рекомендуемый вариант
  для деплоя на Render — просто выставьте `WEBHOOK_URL=true` и ничего
  больше указывать не нужно.
- **Полный URL (например `https://mydomain.example.com`)** → webhook-режим
  с этим базовым URL (полезно, если бот работает за собственным доменом
  или прокси). Путь `/telegram/webhook` добавляется к базовому URL
  автоматически — можно указывать домен как с этим путём, так и без него.

И в webhook-режиме, и в polling-режиме планировщик задач (`JobQueue`) —
ежедневные/еженедельные сводки и очистка памяти — запускается одинаково.

## Локальный запуск

1. Установите Python 3.11+ и PostgreSQL (либо используйте Docker-контейнер
   с Postgres).
2. Склонируйте репозиторий и создайте виртуальное окружение:

   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```

3. Скопируйте `.env.example` в `.env` и заполните как минимум `BOT_TOKEN`
   и `DATABASE_URL`. Для реальной работы модерации/ответов/сводок
   заполните также `AI_BASE_URL`, `AI_API_KEY`, `AI_MODEL`.
4. Оставьте `WEBHOOK_URL` пустым — локально удобнее long polling.
5. Запустите бота:

   ```bash
   python -m app
   ```

   Таблицы в БД создаются автоматически при первом запуске
   (`Base.metadata.create_all`) — отдельных миграций пока нет.
6. Добавьте бота в тестовую группу и выдайте ему права администратора
   **Delete messages** и **Restrict members** (без них удаление
   сообщений и муты работать не будут).

## Деплой на Render (free tier)

Проект содержит готовый `render.yaml` (Blueprint): веб-сервис + бесплатная
база PostgreSQL, обе в регионе `frankfurt`.

1. Запушьте репозиторий (с обновлённым `render.yaml`) в GitHub.
2. В Render: **New → Blueprint**, укажите репозиторий — Render считает
   `render.yaml` и предложит создать сервис `telegram-ai-moderator` и базу
   `telegram-ai-moderator-db`.
3. Перед деплоем Render попросит заполнить переменные с `sync: false`:
   - `BOT_TOKEN` — токен от @BotFather;
   - `AI_API_KEY`, `AI_MODEL` — данные вашего AI-провайдера (можно оставить
     пустыми, если AI-функции пока не нужны — модерация тогда просто не
     будет находить нарушений через AI, эвристики антифлуда/антиповтора
     продолжат работать).
4. `WEBHOOK_URL` в `render.yaml` уже установлен в `true` — после первого
   деплоя бот сам возьмёт публичный адрес сервиса из `RENDER_EXTERNAL_URL`
   и настроит вебхук. Ничего вручную указывать не нужно.
5. `DATABASE_URL` подключается автоматически (`fromDatabase`) — не трогайте.
6. Запустите деплой. Проверьте логи: должны быть строки
   `Application initialized`, `Webhook configured: https://.../telegram/webhook`,
   `Starting HTTP server on 0.0.0.0:...`.
7. Откройте `https://<ваш-сервис>.onrender.com/health` — должен
   вернуться `ok`.
8. Добавьте бота в группу и выдайте права **Delete messages** и
   **Restrict members**.

### Ручная настройка webhook (если не через Render/`WEBHOOK_URL`)

Обычно этого делать не нужно — бот сам вызывает `setWebhook` при старте в
webhook-режиме. Если нужно установить/сбросить его вручную:

```bash
curl -X POST "https://api.telegram.org/bot<BOT_TOKEN>/setWebhook" \
  -d "url=https://<ваш-домен>/telegram/webhook"

curl "https://api.telegram.org/bot<BOT_TOKEN>/deleteWebhook"
```

## Известные ограничения free tier на Render

- **Засыпание сервиса.** Бесплатный веб-сервис Render засыпает примерно
  через 15 минут отсутствия HTTP-трафика. Первое входящее обновление после
  простоя вызовет «холодный старт» (обычно 30–60 секунд) — Telegram может
  посчитать доставку вебхука неудачной и повторить попытку позже; какое-то
  время бот будет казаться неотвечающим. Периодический внешний пинг
  `/health` (например, через внешний uptime-мониторинг) снижает частоту
  засыпаний, но не убирает ограничение полностью.
- **Free PostgreSQL удаляется через 30 дней.** Бесплатная база данных на
  Render автоматически удаляется через 30 дней после создания — вместе с
  ней пропадёт вся история сообщений, настройки групп и статистика.
  Для долгосрочной эксплуатации нужен платный план БД или регулярный
  экспорт/бэкап данных.
- **Нет миграций схемы.** Таблицы создаются через
  `Base.metadata.create_all` при старте. Если в будущем менять модели
  (добавлять колонки и т.п.), потребуется либо ручной `ALTER TABLE`, либо
  внедрение Alembic — на «живой» базе автоматической миграции нет.
- **Модуль ролей не используется.** В `User.role` и
  `app/services/authorization.py` есть задел под систему ролей
  (`user`/`moderator`/`admin`/`owner`), но обработчики команд проверяют
  права исключительно через Telegram (`get_chat_member`), это поле не
  читается и не пишется.
- **`/notifications` — это, по сути, журнал модерации.** Отдельной таблицы
  «уведомлений» с флагом прочитано/непрочитано в проекте нет; команда
  показывает последние записи `moderation_logs` за 24 часа.
